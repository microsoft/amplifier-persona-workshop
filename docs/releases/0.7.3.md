# Persona Workshop 0.7.3

Build and evaluation callers can recover a lost submission reply without starting
another analysis. The service advertises `job-submission-recovery` and accepts an
optional `request_id` on the existing submission endpoints. For the same caller,
project and unchanged request, it returns the existing job and its recorded result.
A changed request under the same key is refused; separate keys still permit
separate jobs within the existing project and concurrency rules.

The existing project jobs endpoint also supports exact lookup by `request_id`.
Lookup does not create or restart work. Missing records remain unknown, and failed,
cancelled or interrupted jobs remain the original jobs. Recovery rechecks current
access and remains valid after a completed build advances the project revision,
including concurrent submissions that finish during validation.

This release uses existing job records and adds no shared service or model calls
for recovery. Existing callers without request keys keep their behavior. Projects,
profiles, account settings and recorded evidence retain their existing formats.
See [the API contract](../ui-api-contract.md#candidate-and-review) for exact request
identity and recovery limits.

Native packages retain the private document runtime and existing update path for
Windows, macOS and Linux on x64 and ARM64. These previews are unsigned and are not
notarized. Controlled job and real-component reference tests do not establish live
provider quality or installed-fleet adoption.
