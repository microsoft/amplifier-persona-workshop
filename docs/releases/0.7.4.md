# Persona Workshop 0.7.4

Existing Linux PAM/HTTPS services can join the native update path through explicit
`adopt-existing prepare`, `apply` and `recover` commands. Preparation captures the
running service and complete download. After its owner stops the service and
reviews pending effects, adoption verifies the original process, child processes
and listener have stopped before replacing the application.

The original service definition, startup preference, executable path, PAM sign-in,
HTTPS configuration, sessions, projects and recorded work are preserved. Queued or
running jobs prevent cutover; historical unknown outcomes remain unchanged and
are never replayed. Verified service health establishes the native installation
baseline. Later releases use the existing **App updates** controls.

Interrupted preparation and lost replies recover the same operation. A failed
start restores the prior executable and runtime without restoring an older
database, so newer work survives. A corrected download can be prepared after a
verified rollback while keeping the earlier operation history. See
[existing-service adoption](../configuration.md#adopt-an-existing-linux-service)
for the supported maintenance flow and recovery commands.

Native packages remain available for Windows, macOS and Linux on x64 and ARM64.
The legacy adoption path is Linux-only; it introduces no shared service, Instance
dependency, provider setup or authentication conversion. Preview packages remain
unsigned and unnotarized.
